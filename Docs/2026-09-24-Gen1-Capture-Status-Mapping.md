# 一代拍照导致录像按钮变化

## 现象和证据

用户提供 `2.mp4`、`aiglass_ble_log_20260924_151749.txt`、`aiglass_connect_log_20260924_151729.txt`。日志版本为 1.1.6 (127)，设备 L1 0022 / MCL010。

视频中两次点击拍照后，录像按钮均出现“录像 → 结束录像 → 录制完成 → 录像”。录像按钮不是用户点击的目标。

第二次操作对应日志：

| 时间 | 事件 |
| --- | --- |
| 15:12:05.359 | 发送一代拍照命令 `0x60` |
| 15:12:05.973 | 适配后 `devstatus0=3`，日志错误标成 `VOICE_RECORDING` |
| 15:12:07.442 | `devstatus0=0`，空闲 |
| 15:12:07.871 | 发送查询文件命令 `0x33` |
| 15:12:08.144 | 适配后 `devstatus0=2`，日志错误标成 `VIDEO_RECORDING` |
| 15:12:09.794 | 收到文件数量 16 |
| 15:12:09.877 | `devstatus0=0`，触发错误的录像完成反馈 |

这个区间没有发送开始录像命令 `0x61`。旧日志的 `devstatus0` 是 App 重建后的通用数据，不能把显示的 `VIDEO_RECORDING` 当作设备真的在录像的证据。结合旧适配器原样传递数值的实现，可还原为一代原始状态 3（拍照）和 2（网络操作）。

## 根因及安卓对照

旧 `Gen1DeviceStatusMapper.toDomainStatus` 返回一代协议枚举，BLE 管理器把其原始 `.rawValue` 直接发给通用 `devstatus0` 解析器。一代原始值与通用域值并不相同：

| 一代原始值 | 含义 | 正确通用值 | 旧 iOS 误判 |
| --- | --- | --- | --- |
| 0 | 空闲 | 0 | 空闲 |
| 1 | 录像 | 2 | 拍照 |
| 2 | 网络操作 | 7 | 录像 |
| 3 | 拍照 | 1 | 录音 |
| 4 | 关机 | 8 | 文件导入 |

安卓 `Gen1Protocol.kt` 的 mapper 显式执行这张转换表。`HomeFragment.handleDeviceStatusChanged` 只在录像状态更新录像按钮，不把网络操作视为录像。

iOS 错误收到录像状态后，`HomeView.videoButtonTitle` 显示“结束录像”；随后 `videoRecording → standby` 又调用 `finishVideoCaptureSuccess`，显示“录制完成”。

## 修改与验证

- 显式转换一代原始值到通用域值，返回类型改名为 `Gen1DomainDeviceStatus`，明确其 `.rawValue` 不代表一代原始值。
- 通用状态补齐网络操作和关机，保留原有二代 0–6 数值；首页沿用忙提示处理这两种状态。
- BLE 日志新增命令号、原始状态、转换后的数值及名称，避免只看到转换后的标签。
- 回归测试经过真实 `mapper → buildPacket → parseDevStatus`，覆盖全映射、拍照后查文件、录像、ACK 一致性、未知值和二代兼容。
- Gen1 测试 328 个断言通过；通用通知组帧测试 134 个断言通过。iPhoneOS Debug 无签名编译通过。

真机仍需复测：拍照后录像标题保持“录像”；真实开始/结束录像正常变化；设备按键拍照、按键录像及拍照后文件列表更新正常。
