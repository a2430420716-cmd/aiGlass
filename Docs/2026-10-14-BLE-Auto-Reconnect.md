# 已绑定眼镜 BLE 自动回连

## 故障依据

2026-10-09 连接日志来自 1.1.6 (131)，目标 L1 0022。在 21:56:49.771—21:58:28.145 期间，蓝牙 poweredOn、权限已授权、autoReconnect=true、userDisconnect=false，能够取回缓存目标，但系统已连接外设查询为空。24 次快照包含 connect_not_sent，没有发起连接或进入服务发现。经典蓝牙已连接不能替代目标 BLE 的连接请求。

## 修改

- 启动、首页刷新、回前台和断线监控继续优先接管系统已连接的目标。
- 查询为空时，只针对本地保存的 UUID 发起 CoreBluetooth connect，不再要求系统 BLE 先连接。
- 重复刷新复用已挂起的连接请求。没有当前 BLE 连接证据时，不按 15/20 秒计时取消设备离线期间的连接请求；didConnect 后仍使用原有服务发现和通知订阅超时、恢复策略。
- 取不到缓存外设时，执行 15 秒扫描，只接受保存的 UUID，不按名字或型号自动接管其它眼镜。扫描起点之间至少间隔 30 秒；缓存稍后可用时无需等待扫描冷却。
- 实际 didFailToConnect 后，缺少系统连接证据的回连等待 30 秒再试。成功 ready 后清除冷却。
- 每轮最多首次连接加 3 次自动重试。扫描找不到目标、连接失败及自动 GATT 重建前的失败共用预算；用尽后停止监控和自动接管，首页提示“自动重连已重试 3 次，请点击重试”。重复进入首页、回前台、系统连接事件不能绕过上限。连接成功、新配对或用户手动重连才重置预算。离线期间同一个挂起 connect 不算重复重试。
- 保留主动取消、解绑、退登、新配对、手动恢复及一代 OTA 的所有权保护。自动扫描在停止扫描、蓝牙不可用或进入 ready 时清理。
- 连接事件注册日志展示完整服务过滤列表，包括一代 AE3A 和二代服务。

## 验证

Windows 环境已执行 git diff --check，并对管理器、恢复策略、回归测试进行 Swift 语法树检查，均通过。新增冷却回归用例覆盖：重复刷新不推迟扫描截止时间、扫描冷却不阻塞缓存连接、连接失败冷却、成功后复位。

## 真机验收

1. 一代、二代分别测试：保留绑定，眼镜关机再开，经典音频先恢复，App 无需再点配对应进入 didConnect → 服务发现 → 通知订阅 → ready。
2. 冷启动和回前台重复进入首页：查询为空时应出现 reconnect saved BLE without system connection 和一次 arm iOS auto-connect (standing)，不能只显示等待系统证据。
3. 眼镜离开范围超过一分钟再返回：等待期间保留同一连接请求，返回后恢复；不能每 15 秒反复取消。
4. 缓存外设缺失时：仅扫描绑定 UUID，15 秒无结果退出并冷却，旁边同名眼镜不能被接管。
5. 取消、解绑、退出登录后开机：不得自动连接旧设备。检查正常配对、手动重试、一代 OTA、二代导图回连没有被抢占。
6. 已连接但服务发现或订阅失败时：仍能触发既有 GATT 超时恢复。

## 边界

自动回连要求眼镜恢复可连接 BLE 广播或系统能恢复对应 LE 连接。系统“忽略设备”导致 UUID 改变时，不会按名称冒认新 UUID，仍需用户配对。iOS 用户强制退出 App 后的行为由系统管理，本修改不保证强制退出期间执行 App 回连代码。
