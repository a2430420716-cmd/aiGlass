# 二代配对身份读取与原始通知诊断

## 2026-09-22 现场证据

1.1.6（125）的连接日志显示多次手动配对均进入 BLE READY；BLE 日志中 136 条 `getdevinfo` 都只保留了 20 字节，其中 17 次 SN 查询没有完整结果。绑定需要完整 SN，之前缺失 SN 时只打印日志，界面可一直等待。

旧 BLE 导出在拆帧之后记录，不能证明外设未发送剩余字节。用合成 34 字节 SN 帧按 20 + 14 字节调用当前拆帧器，首包进入补读分支，后 14 字节不会产生协议帧，也没有旧版导出日志。是否发生在这副真机上仍待原始回调证据确认。

Android 二代 `BleManager.extractNotificationFrames` 同样没有跨通知缓存；它请求 MTU 512，首次设备信息查询 SN 优先，首条延迟 3 秒，后续间隔 3 秒。一代的流式组包是另一条协议路径。本次不根据猜测更改二代组包和命令时序。

## 本次修改

- 在 `didUpdateValueFor` 拆帧和旧连接过滤之前记录原始回调，包括无命令头及不足 12 字节的值。记录回调采集时间、外设/特征 UUID、是否为当前连接、原始长度、前 64 字节及省略长度。
- 每条连接最多保留 256 次 RAW 记录，超限明确提示；重置连接时恢复预算。已识别的音频/图像命令仅记长度，不输出载荷。
- ATT 错误单独记录；回调有错误时，`CBCharacteristic.value` 的缓存字节不会被当作新数据。read 和 notify 共用回调，因此记录 `readPending/readIssued` 作为上下文，不把等待期间的通知误标为已确认的 read 响应。
- 补读的调度、执行、取消、次数耗尽、不支持读取以及设备身份缺失均进入可导出日志。延迟补读带请求 ID、外设和特征对象校验，失效的调度不再操作新连接。
- READY 记录系统报告的最大写入长度与通知特征属性；这些写入上限不等于已验证的接收通知大小。
- 点选配对设备后，等待完整身份最多 60 秒。超时结束加载并提示；只断开本次选择且未绑定的目标，清除该临时目标的重连记录，再恢复账号里已有设备。
- 配对会话 token 和 UUID 隔离超时、取消、重试、切设备、退登及迟到身份；进入服务器绑定后取消身份超时，旧异步结果不更新新会话界面。

## 验证与复测

自动化覆盖原始 20 + 14 字节日志、短包、错误携带旧缓存值、音频/图像省略、限流与重置、日志导出及时间戳，以及配对超时后迟到 SN、旧会话定时器、切设备和重复绑定。

```sh
bash Tests/run-bluetooth-regression-tests.sh
bash Tests/run-gen1-tests.sh
```

复现后立即在 D 浮窗导出“连接”和“蓝牙”日志。查看 `RAW · before framing` 是否在 20 字节首包后出现无命令头续包，并同时检查 `notify read scheduled/issued/cancelled` 与 ATT 错误。若确有续包，再依据实测边界加入组包；若未到达，继续定位链路与固件发送/补读。此修改不代表“二代全部控制失败”根因已确认或真机配对已恢复。
