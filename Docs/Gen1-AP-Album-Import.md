# 一代眼镜 AP 相册导入

更新：2026-09-24。依据用户提供的《AP 导图流程说明（iOS App 开发）》和 Android 一代 TCP 实现。用户已确认：热点凭证随 **`0x37` 应答**返回；不再发送文档旧段落中的 `0x10`。

## 实现范围与二代隔离

`MediaImportManager` 仅在 `deviceGeneration == .gen1G5K61` 时进入新 AP/TCP 分支。二代保留原有热点、HTTP 文件传输、逆时针方向校正和 PixSmart 处理流程。

新增一代专用组件：

- `Gen1HotspotSession`：BLE 热点业务会话、应答分流、超时和收尾。
- `Gen1HotspotCleanup`：按设备 UUID 持有跨导入任务的收尾状态，等待关闭回包和后续稳定空闲，未结束前禁止重新开热点和启动升级。
- `Gen1WifiGatewayResolver` / `Gen1WifiGatewayPolicy`：核对实际 SSID、Wi-Fi 路径和系统报告的网关。
- `Gen1MediaTCPProtocol` / `Gen1MediaTCPClient`：协议和串行传输。
- `Gen1ImportInbox` / `Gen1MediaStaging`：完整原件恢复、不可覆盖的归档和重试去重。
- `Gen1VideoImportPipeline` / `Gen1MediaOrientation` / `MediaLibrary.importGen1Original`：一代视频防抖、原音轨合成、方向校正、缩略图和相册落盘。

公共 Wi-Fi 配置函数只新增可选超时和日志参数，二代调用保持原默认值。新增 `com.apple.developer.networking.wifi-info` entitlement；当前开发描述文件已包含此权限。生成的 App Info.plist 已有本地网络权限说明。

## 协议约定

| 步骤 | 当前实现 |
| --- | --- |
| 开热点 | BLE `AA 02 03 37 00 00 D0 5B`，空负载 |
| 凭证应答 | 外层重组、来源及 CRC 校验后，解析 `0x37` 的 ASCII `SSID/password`；仅切第一个 `/`，不裁剪 SSID |
| 热点失败 | 任意单字节应答均失败；`01/02/03` 分别提示脚本、hostapd、DHCP 失败；`E3` 提示设备忙，本次被拒绝，不补发关闭；未知码打印十六进制 |
| 录音复用 | 请求 `0x37` 仅负载长度为 1 时作为录音命令；AP 活跃时独占同目标的 `0x37` 应答，结束后保留短暂迟到应答隔离期 |
| 蓝牙文件列表 | `0x33` 空负载；20 个文件名一批的回复累积、去重，避免下一批覆盖上一批 |
| 加入热点 | `NEHotspotConfiguration`；确认当前 SSID 精确匹配后，读取 Wi-Fi 专用 `NWPath` 的 IPv4 网关 |
| 网关 | 不硬编码 `192.168.4.1`，不由手机地址推算 `.1`，不采用蜂窝或其他热点的路径 |
| 文件通道 | TCP `网关:8556`，仅使用 Wi-Fi 接口；实际文件列表以 TCP `0x0003` 返回为准 |
| 文件请求 | `0x0001`，负载为 UTF-8 文件名；`external_length` 是文件名字节数 |
| 文件响应 | 文件字节数 = `total_length - 20 - 文件名字节数`；附加长度不重复相减 |
| 保活 | 独立任务每 2 秒发送 `0x0006`，文件落盘使用独立 actor；按长度读取，文件内容中的 `AF8C` 不作为分隔符 |
| 结束 | 本批文件完成后发送一次 `0x0007`，释放 TCP 和手机热点配置；仅本次曾实际提交开启请求且未收到忙拒绝时，交给收尾协调器关闭同一眼镜热点 |

TCP 使用 18 字节大端帧头和固定 `AF8C` 帧尾。请求使用 version=1、source=2、target=3；接收除标准 3→2 外，兼容 Android 历史版本 version/source/target 全为零的帧，拒绝混合零值和反向回显。

文档“单个文件结束”和 Android 的批次结束行为存在表述差异：当前按 Android 的完整批次发送一次 `0x0007`。必须通过新版固件多文件真机测试确认，不将本地测试视为固件兼容证明。

## 原件安全与恢复

设备发送完文件可能自动删除原件，因此不依赖再次下载：

1. 请求文件前，按账号、眼镜 UUID、传输 UUID 写入 `Documents/Gen1ImportInbox` 元数据。
2. TCP 分块写入 `.partial`。文件名、长度、帧尾全部校验且同步落盘后，原子重命名为完整文件；已有文件不覆盖。
3. 在 `Documents/Album/gen1-originals` 保存未修改原件和 SHA-256 归档凭据，再生成展示文件、缩略图并原子提交相册清单。
4. 开启自动保存时继续保存系统相册；成功后才清理对应 Inbox。处理或 Photos 保存失败，完整原件仍可恢复。
5. “恢复”从手机原件重试，不依赖 BLE、电量或眼镜空闲；“导入眼镜文件”独立启动新导入，坏文件不会永久堵住新文件。

`.partial` 保留供故障诊断，但不作为完整文件恢复；协议未提供偏移续传，本实现不声称支持断点续传。相同 Inbox 原件重试复用相册 ID，避免重复创建 App 相册项目。系统 Photos 保存成功与 App 清理之间若被强杀，仍可能在下次重试时产生 Photos 副本。

原始归档当前长期保留，包括删除相册展示项后，以避免误删设备侧已经删除的源数据；后续如增加原件清理功能，需要明确删除意图和保留策略。

BLE 单独断开允许已建立的 TCP 继续。解绑、切换眼镜、切换账号或退出登录则使本次身份失效，停止后续网络操作和 Photos 保存；处理中已经下载的原件保留。收尾不向另一副眼镜发送关热点命令。

### 2026-09-29 收尾与重试时序修复

现场日志显示 `0x38` 回包比请求晚约 30–33 秒，旧实现发送入队后立即结束，导致回包落入下一次开启热点期间。现在：

- 收尾期间显示“正在等待眼镜热点关闭”，保持导入互斥。协调器使用独立任务，父导入取消不会跳过等待。
- 同一设备同一待完成收尾只提交一次 `0x38`。等待上限 75 秒；超时保留阻断，再次点击导入会恢复状态检查，不重发关闭、不发新的 `0x37`。切设备、退出账号、GATT 断开和导入结束均不清除待完成记录；失去原账号/设备授权时暂停发送。
- `0x38` 的 `02` 含义尚未获得固件方确认，**不作为关闭成功码**。收到单字节非忙回包后，主动查询 `0x72`；距关闭回包至少 20 秒、连续新鲜查询空闲至少 5 秒，且最后一次查询仍为空闲，才解除阻断。任意非空闲状态、查询超时、断线都重置空闲证据；`0x73` 单次空闲通知不放行。这是根据现有现场时序采取的保守恢复条件，仍需固件协议和真机确认。
- 无回包、持续忙或收尾超时均明确提示。持续无法恢复时需重启眼镜和 App；记录只在当前 App 进程保存，单独重启 App 不能证明眼镜已结束旧操作。
- 隔离待收尾设备的迟到 `0x37`，避免误当录音回包；主固件 OTA、蓝牙 OTA 和业务命令不能绕过收尾。禁止共享旧任务直接下发无所属会话的一代 `0x38`；二代发送及导入路径不变。

该修复消除 App 已知的开/关交叠，不据此认定系统“无法加入网络”必然消失。热点认证和 DHCP 故障仍需要固件侧日志确认。

本轮验证：新增热点收尾测试 124 条断言通过，覆盖真实延迟时序、取消、并发关闭、超时、账号/设备切换、查询未入队和查询无响应；一代完整测试和共享蓝牙回归通过，最终 iOS 无签名编译成功。与本轮改动前快照比对，二代相册导入和 OTA 主流程保持不变。导入弹窗同步移除“一代/二代”分类，只描述错误原因与重试操作。

## 视频防抖与媒体处理

已核实 Android 的 `SxsMediaProcessor` 对一代实际启用了防抖，两代共用 `libpixsmart_vs_pv`，通过 `setUseGen2Config` 切换参数。之前“iOS SDK 缺少一代配置”的判断已更正：底层 `PIXSMART_VS_PV_PARAM` 已支持所需参数，缺少的是应用封装的一代入口。

| 参数 | 一代 | 二代（保留原值） |
| --- | --- | --- |
| outScale | 0.8 | 0.8 |
| dregScale | 240 / max(width, height) | 360 / max(width, height) |
| stdev | 3 | 3 |
| colorStandard | BT709_FULLRANGE | BT709 |
| 导入方向校正 | 顺时针 90° | 逆时针 90° |

一代调用独立 `stabilizeGen1Video` 入口。使用项目已有的 iOS PixSmart framework 和 iOS 许可证，不复制 Android `.so` 或许可证。进入眼镜热点前在后台预鉴权，失败时仍允许原件导入。

视频先按原始尺寸防抖，再从未修改原件补回音轨，最后顺时针旋转 90°。SDK 输出视频后，音轨合成和旋转使用 passthrough；不再次做防抖编码。原生 GL 坐标沿用 iOS 的处理，不机械叠加 Android 纹理矩阵的上下翻转。缩略图从最终视频生成。

授权、短视频、初始化、解码、GL 或防抖输出合成失败时回退原视频，保留原音轨和方向校正。若原视频本身也无法解码或导出，则保留原件并报告失败，不计为成功导入。

原生一代处理增加输入尺寸/帧数、缓冲区、写入结果检查；无输出不补帧。取消从导入任务传到实际媒体处理任务和 SDK 会话；原生读写资源清理结束后才回调，避免仍在写入时清理临时文件。30 分钟超时请求协作取消；同步厂商调用若未返回，无法安全强杀。按 Android 的保护逻辑，初始化异常或零输入帧时跳过可能崩溃的 `Uninit`，该异常状态可能残留厂商句柄，日志记录原因。

二代使用原入口，算法参数及原生处理分支保留；新增一代会话期间禁止并行启动另一个视频引擎。

本轮实现 AP 相册照片/视频导入；旧固件 Wi-Fi Direct、STA 配网和设备录音文件导入不属于这个通道。
